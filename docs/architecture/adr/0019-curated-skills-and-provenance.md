# ADR-0019 — Curated skill set, provenance lock and attribution

- Status: Accepted (pending PO review of the open decisions below)
- Date: 2026-11-10
- Issue: #37 (OMI-031), epic #36 (EP-06), milestone M4 — Full lifecycle
- Context documents: `docs/product/product-overview.md` §7; `docs/architecture/architecture.md` §3,
  §4, §6.2, §15 (ADR-0009 "curate skills into our own set"); `docs/engineering/design-patterns.md`
  §14; ADR-0016 (context packet `skillsManifest` entries `{id, version, sha256}`)
- Out of scope: the roles and workflows that load these skills (later Issues), and any runtime
  skill loader or `skillsManifest` builder

## Context

product-overview §7 names four reference sources (Superpowers, Taste, Ponytail, UI UX Pro Max) and
requires a curated, adapted set with provenance, not four installed frameworks that all try to
orchestrate. ADR-0009 recorded that intent without a file. The four sources are cloned at pinned
commits as untrusted data; all have an MIT licence at the repository root, and one nested
directory (`ui-styling` in UI UX Pro Max) carries Apache-2.0.

## Decision

1. **Selection.** Nine skills ship under `templates/project/.omi-squad/skills/<id>/SKILL.md`, each a
   single file, chosen for the roles in product-overview §6 (analysis, development, verification,
   debugging, review, design). Each is a short, adapted text, not a copy. Nothing else from the
   upstream repositories is imported: no scripts, hooks, data files, fonts, images, logos or
   plugin files.
2. **Orchestration is removed.** The Coordinator and runtime own dispatch, review gates, branches,
   worktrees, commit/push/merge and approval. Skill text that makes an agent do those is dropped or
   rewritten: mandatory "invoke a skill before any response", spawning subagents, choosing or
   creating branches and worktrees, committing, pushing or merging, "finishing a development
   branch", and asking the user directly. Open questions and escalations go to the Coordinator
   through the step's report. Skills never weaken `AGENTS.md` rules or PO approval. Every exclusion
   is recorded with its reason in the lock file.
3. **Licence is checked per resource.** A resource is taken only if it sits under an MIT licence
   with a recorded copyright line, and only its text is used. Directories with a different licence
   (`ui-styling`, Apache-2.0), third-party imagery or brand icons, font data and executable
   scripts are excluded.
4. **Attribution.** `skills/NOTICE.md` reproduces each source's MIT copyright and permission notice
   verbatim (taken from the pinned `LICENSE` file), the repository URL and the commit referenced.
5. **Provenance lock.** `provenance/skills.lock.json` (schema version 1) records, for each source,
   the repository, commit, licence, copyright line and the LICENSE file's sha256; for each skill,
   its `id`, `version`, `sha256`, source paths with their sha256 at the pinned commit, local files
   with sha256, and whether and how it was modified; and the list of exclusions.
   - A skill's `sha256` is the SHA-256 of the lines `<path> <file sha256>\n` over its files in the
     listed order. `{id, version, sha256}` can therefore be copied into a `skillsManifest` entry
     unchanged (the `id` is a valid slug, `sha256` is lowercase hex).
   - `version` is the local curation version; it is bumped on any content change.
6. **Guard.** `tests/unit/templates/skills-lock.test.ts` fails when a skill file differs from the
   lock, when a file under `skills/` has no lock entry, when a listed file is missing, when NOTICE
   changes, or when a source lacks its copyright or commit in NOTICE. The lock is regenerated by
   hand-reviewed edits for now; a generator can be added when a second curation round needs it.

## Consequences

- Changing a skill means changing the file, bumping its `version` and refreshing the hashes in the
  lock in the same PR; the test only checks the hash, so bumping `version` is a review item.
- Updating to a newer upstream commit is a new curation round: re-review the diff, then update the
  commit, the original sha256 values and the skills.
- Skills are guidance for agents, not gates. Gates stay in the runtime (architecture.md §6.1).

## Open decisions for the PO

- Whether the `ponytail-audit`, `ponytail-debt` and the UI UX Pro Max `design`/`design-system`
  skills should be curated in a later round (excluded now as outside the selected roles).
- Whether a Taste-style browser check (screenshots at several widths) should become a runtime
  capability later; the skill currently only asks the agent to use tools the project already has.
